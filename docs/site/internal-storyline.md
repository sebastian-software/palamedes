# Internal Messaging Storyline

This page exists to turn the public messaging spine into a later internal deck
without reinventing the narrative.

## Ten-Slide Executive Story

1. The problem: i18n semantics often spread across authoring, catalogs, runtime, and host wiring
2. The thesis: Palamedes keeps one coherent model from source to runtime
3. The host story: first-party adapters connect that model without redefining it
4. The architectural core: native core, thin adapters, delegated catalog semantics
5. The runtime story: one runtime model, one identity model
6. The confidence story: the verified example matrix proves that no single adapter defines the core
7. The evidence story: screenshots, CI flows, benchmarks, ADRs
8. The comparison story: Lingui closest, `next-intl` different center, GT broader category
9. Product layers: Palamedes is the local open-source foundation; Palamedes+ is the planned optional managed layer
10. What to do next: sharpen homepage/docs, expand verification, reuse this story in a deck later

## Headline Options

- A modern i18n stack that stays consistent across frameworks
- Cross-framework i18n without a fragmented mental model
- One runtime model for modern JavaScript i18n
- One coherent i18n model from source to runtime
- The verified path to cleaner i18n architecture
