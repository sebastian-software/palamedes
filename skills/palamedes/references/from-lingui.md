# Lingui to Palamedes

Apply this together with the chosen host reference. Preserve the host framework;
this migrates its i18n integration, not the framework itself.

## Inventory before changing catalogs

Inspect Lingui version, config, formatter options, Babel/SWC/Vite plugins,
macro imports, runtime providers/activation, `.po` imports, and CI/TMS scripts.
Search for core and React macros, mixed `@lingui/macro`, `i18n._`, `useLingui`,
`I18nProvider`, `msg`, `defineMessage`, explicit IDs, and dynamic descriptor/ID
lookups. Read source-locale catalogs alongside translated catalogs. Source
messages for explicit IDs may be in source-locale `msgstr` or extracted source
code; a translated `msgstr` is not evidence of its source message.

Take a recoverable snapshot before catalog edits. Produce a mapping table for
every active old identity: old ID/context, source message, target context,
origins, and translations by locale. Palamedes public identity is
`message + context`; internal compiled keys are not authoring IDs.

Lingui PO encoding varies with formatter settings. Generated IDs often already
have source text in `msgid`; explicit IDs can be `msgid "checkout.cta"` with
`js-lingui-explicit-id` comments, or be the default without that comment. Read
the actual formatter/config rather than recognizing IDs by spelling alone.
Remap explicit-ID entries to their verified source text and chosen context in
**every locale**, preserving `msgstr`, translator comments, flags, ICU quoting,
and relevant metadata. References and framework-specific generated annotations
may be regenerated by extraction. Remove obsolete Lingui ID annotations only
after the mapping is verified.

Different old IDs can collapse to the same target identity. Compare all locale
translations before merging; use semantically meaningful contexts when messages
must stay distinct. Conflicting translations, missing source messages, dynamic
ID consumers, or external TMS contracts require a real decision. Stop that part
of the migration and report the exact conflict. Do not guess, discard entries,
or run `--force-clean` to make the diff look clean. Keep Lingui operational until
the unresolved consumers can be migrated.

## Imports and evaluation time

Move core macros to `@palamedes/core/macro` and JSX macros to
`@palamedes/react/macro`. Split mixed `@lingui/macro` imports. Palamedes leaves
Lingui imports untouched, so successful extraction of other messages does not
prove all imports migrated.

```ts
// src/labels.ts
import { t } from "@palamedes/core/macro";

export function checkoutLabel() {
  return t({ message: "Buy now", context: "checkout button" });
}
```

```tsx
// src/Offers.tsx
import { plural } from "@palamedes/core/macro";
import { Trans } from "@palamedes/react/macro";
import { checkoutLabel } from "./labels";

export function Offers({ count, name }: { count: number; name: string }) {
  return (
    <section>
      <p>
        <Trans>Hello {name}</Trans>
      </p>
      <p>{plural(count, { one: "# offer", other: "# offers" })}</p>
      <button type="button">{checkoutLabel()}</button>
    </section>
  );
}
```

Replace deferred `msg`/`defineMessage` descriptors with translation functions
called in the active render/request scope. Update callers too: a function is
not a descriptor that can still be passed to `i18n._`. Move eager `t`, `plural`,
`select`, `selectOrdinal`, and JSX choice macros inside functions, methods, or
callbacks. Module-level and class-field eager translations fail. `<Trans>` can
remain at module scope because it resolves when rendered. Call `getI18n()`
inside the active function/component, never at module load.

Preserve rich-text structure and named placeholders. If a legacy PO entry uses
numeric placeholders, map its translation placeholders to the names produced
by migrated extraction; do not keep incompatible translated ICU strings just
because the prose still looks right. Compare extracted source identities before
accepting a catalog mapping. Preserve natural apostrophes and ICU quoting.

## Replace host wiring and verify

Use the host reference's automatic adapter. In Next.js, await
`createNextServerI18n` in translated server entry points and initialize actions
separately via `palamedes.server.ts`. In Vite, set document `lang` before entry
evaluation. Preserve locale precedence and keep getters read-only.

After identity remapping and source changes, run `pmds extract` without cleaning
away uncertain entries. Compare all active translations and metadata against
the snapshot/mapping. Run extraction a second time and confirm stability. Build
and render both locales, including deferred labels, plural/interpolation/rich
text, and Next actions/client code if present. Inspect the entire app for
remaining Lingui imports, descriptors, runtime calls, config, and CI/TMS paths.
Only then remove unused Lingui packages and scripts. If a supported form cannot
be migrated, retain it explicitly and report the remaining migration scope.
